# Telescope 프론트엔드

Telescope 화면입니다. 흐름은 (사용자) 근거 데이터 수집 → (AI) 검토 → 질문 → 평가입니다. 부서 사람들이 페이지의 캔버스에 공시·IR·뉴스·사내 자료를 모으고 메모와 연결을 붙이면, 분석 화면에서 AI가 근거를 검토(주장 · 근거 충분/부족 · 지적 · 인사이트)하고 애널리스트 예상 질문을 만들며, 다음 분기 자료가 들어오면 평가합니다. 흐름은 [기획서](../docs/planning/기획서.md)를, 화면 구조는 [IA](../docs/frontend/ia.md)를, 서버 API는 [API 명세](../docs/frontend/api-spec.md)를 따릅니다.

- 기술: Vue 3 + TypeScript, Vue Flow(캔버스), Pinia(상태), Vite(개발 서버·빌드), Electron(데스크톱 창)
- 띄우는 곳: 브라우저(`npm run dev`)와 데스크톱 앱(`npm run electron:dev`)
- 지금 상태: backend 연결 전입니다. 서버가 할 일은 `src/local/`이 브라우저 안에서 대신하고, 공시 표 · IR · 사내 자료의 수치 · 기사 · 링크는 팀이 만든 목업 자료입니다(5장, 원본은 6장). 자료 검색의 대시보드 · 회사 재무 값과 썸네일 뉴스 13건은 v01-stella 데모에서 가져온 실제 공시값 · 기사입니다(`src/local/dart.ts`, `src/local/news.json`).

## 1. 실행

`frontend/` 폴더에서 실행합니다. Node 22.18 이상이 필요합니다.

```bash
cd frontend
npm install          # 처음 한 번. Electron 실행 파일도 함께 받음
```

### 1.1 브라우저로 띄우기 (실시간 반영)

```bash
npm run dev
```

터미널에 나오는 `http://localhost:5173`을 브라우저로 엽니다. 포트는 5173으로 고정이라, 이미 다른 앱이 쓰고 있으면 서버가 뜨지 않고 멈춥니다(Electron이 같은 주소를 열기 때문). `src/` 안의 `.vue`·`.ts`·`.css`를 저장하면 새로고침 없이 화면에 바로 반영됩니다(HMR). 끄려면 그 터미널에서 Ctrl+C를 누릅니다.

### 1.2 Electron으로 띄우기

```bash
npm run electron:dev   # 개발 서버 + Electron 창. 코드를 저장하면 창에도 바로 반영
npm run electron       # 배포용 빌드(dist/) 후 그 결과를 Electron 창으로 엶. 서버 없음
```

- `electron:dev`는 Vite 개발 서버와 Electron 창을 같이 띄웁니다. 서버가 뜰 때까지 창이 0.5초마다 다시 연결합니다. 창을 닫아도 개발 서버는 남으니 터미널에서 Ctrl+C로 함께 끕니다.
- 이미 `npm run dev`를 켜 둔 상태라면 `npm run electron:open -- --dev`로 창만 띄웁니다.
- Electron 진입 파일은 `electron/main.cjs`입니다. `package.json`이 ES 모듈 설정이라 CommonJS(`.cjs`)로 둡니다.
- 브라우저, Electron 개발 서버 창, Electron 빌드 창은 저장소(localStorage)가 서로 다릅니다. 한 곳에서 만든 페이지는 다른 곳에서 보이지 않습니다.

### 1.3 빌드

| 명령 | 결과 | 쓰는 곳 |
|---|---|---|
| `npm run build` | 타입 검사 + `dist/` | 배포(`Dockerfile`의 nginx), `npm run electron` |
| `npm run build:html` | 타입 검사 + `docs/frontend/demo.html` 한 파일 | 기획 문서에 붙이는 공유용. 서버 없이 더블클릭으로 열림 |
| `npm run type-check` | 타입 검사만 | — |
| `npm test` | 단위 테스트(vitest). 서버 연동 계층(`src/sync/`)의 묶음·재전송·글 충돌·번호 확인·원격 반영 | — |

빌드는 상대 경로(`base: './'`)로 나와서 nginx 루트 배포와 Electron 파일 열기에 모두 쓸 수 있습니다.

| 순서 | 할 일 | 보이는 것 |

| 1 | 미리 들어 있는 계정(사번 `1001`, 이재무)으로 `로그인` → 페이지 홈 `+ 새 페이지` → 이름 · 기준 시점 · 편집할 사람 정하고 `만들기` | 캔버스 화면. 헤더에 제목 · 기준 시점, 헤더 오른쪽 `[캔버스 | 분석]` 전환 |
| 2 | 오른쪽 사이드바 위 `예시 불러오기` | 공시 표 9장, 비교 3장, 시각화 1장, IR·뉴스·사내 자료 4장, 부서장 메모 카드 1장, 연결 4개 |
| 3 | 오른쪽 사이드바 탭 `회사 재무` · `DART` · `인사이트`에서 패널 · 뉴스를 캔버스로 끌어 놓기 | 대시보드 카드 · 문서 카드 |

| 5 | 검색창 `+` → 파일 세 개(`a.exe`, `삼성전자 계획.txt`, `SKT 설비.txt`) | `포맷 불일치` · `회사 불일치` · `통과`. 통과한 것만 `캔버스에 올리기` |
| 6 | 카드를 눌러 오른쪽 위 `+` → 메모 카드, 선을 눌러 `메모 입력` | 메모 카드 · 선 라벨 `메모`(노랑), 왼쪽 `메모` 탭 목록 |
| 7 | Shift를 누른 채 공시 표 2장 클릭 → `시각화 생성` (또는 `표 생성`) | 시각화 · 비교 카드. 공통 계정이 없으면 행을 그대로 모은 `표 모음`. 비교 카드 ✓ · ✗로 대응 확정 · 거부 |
| 8 | 하단 ★(분석하기) | 분석 화면(v01 보고서 모양). 프로세스 바 검토 → 질문이 끝까지 채워지고 평가는 점선 뒤 회색. 분석 보고서에 총평 · 주장별 검토 · 지적 · 메모 분류 · AI 인사이트, 상단 `내보내기`로 정리 글 복사 · Markdown |
| 9 | 헤더 `캔버스` | 지적이 카드 위 빨간 라벨과 테두리로. 라벨을 누르면 분석의 그 항목 |
| 10 | 프로세스 바 `질문` → `평가` → `다음 분기 자료 반영 (데모)` | 애널리스트 리포트 형식 질문(Markdown), 2Q26 쟁점 대비 적중 · 놓침, 가정과 실적 |
| 11 | 캔버스를 고치고 분석으로 | "캔버스가 변경되었습니다." `업데이트`(같은 세션의 v2) · `새로 분석하기`(새 세션), 세션 줄 휴지통으로 목록에서 숨기기 |
| 12 | 헤더 정보 아이콘 → `최예산`(2001) 보기 가능으로 초대 → 2001로 다시 로그인 | `공유받은 페이지`에서 보기 전용, 분석 세션은 각자 것만 |

처음부터 다시 보려면 캔버스 왼쪽 아래 휴지통 → `전체 지우기`를 누르거나 localStorage의 `telescope-canvas:v1`, `telescope-analyses:v1`을 지웁니다.

## 3. 화면 구성

```
┌ 헤더: 로고(홈) · 페이지 제목 · [기준 시점] ····································· (i) 페이지 정보 ┐
├────┬──────────────┬───────────────────────────────────────┬──────────────────────────┤
│레일 │ 근거 데이터    │ [▯]                 자동 배치·비우기·단위 [▯] │ 자료 검색                  │
│캔버스│ 메모          │            캔버스                       │ [대시보드|회사 재무|인사이트]  │
│분석 │              │ 범례  [자료 추가 | 메모 | 분석하기]   − % + │ [+ | 통합 검색]             │
└────┴──────────────┴───────────────────────────────────────┴──────────────────────────┘
분석: 레일 · 세션 목록 · (캔버스 변경 안내) · 프로세스 바 검토─질문─평가 · 검토 / 질문 리포트 / 평가
```

- **로그인**: 사번과 비밀번호를 넣습니다. 지금은 비밀번호를 검사하지 않고, 없는 사번이면 "사번을 확인하세요"가 나옵니다. 사번 `1001`이 미리 입력되어 있습니다.

  | 부서 | 사용자 (직무) |
  |---|---|
  | 네트워크센터 | 이재무 (재무기획), 박망 (네트워크 기술), 김센터 (부서장) |
  | AIDC사업본부 | 최예산 (재무기획), 정데이터 (AIDC 사업), 한본부 (부서장) |
  | 세일즈마케팅본부 | 오마케 (재무기획), 윤영업 (세일즈) |
  | 프로덕트브랜드본부 | 서기획 (재무기획), 강상품 (상품) |

- **페이지 홈**: 볼 수 있는 페이지를 타일로 봅니다. 페이지 하나 = 캔버스 + 분석. `최근` · `내가 만든 페이지` · `공유받은 페이지`로 거르고, `+ 새 페이지`로 이름 · 기준 시점 · 편집할 사람을 정해 만듭니다.
- **헤더**: 로고를 누르면 홈. 제목은 두 번 눌러 바꿉니다. 오른쪽 정보 아이콘은 페이지 정보(이름 · 기준 시점 · 권한 · 수정)와 협업자 편집(초대 · 권한)을 한 팝오버로 엽니다. 공유 설정은 소유자만 바꾸고, 페이지는 소유자와 초대한 사람만 볼 수 있습니다.
- **화면 전환**: 헤더 정보 아이콘 옆 `[캔버스 | 분석]`. 마지막 분석 뒤 캔버스가 바뀌면 `분석`에 빨간 점.
- **캔버스**: 사이드바는 머리 안 버튼으로 접고, 접혔을 때만 헤더 아래 플로팅 버튼으로 엽니다. 오른쪽 사이드바는 처음 절반 폭, 경계선을 끌어 폭 조정, ⌘K로 열고 닫기. 하단 가운데 아이콘 도구(자료 추가 · 메모 · 분석하기, 호버 설명).
  - 카드를 누르면 이어진 카드만 성격색으로 밝아지고 오른쪽 위 `+`(메모 카드 달기)가 나옵니다. Shift를 누른 채 누르면 여러 장 고르고, 두 장 이상이면 `표 생성` · `시각화 생성`(공통 계정이 없으면 표 그대로), 메모 1장을 함께 고르면 `메모 연결`(메모를 고른 카드 모두에 이음).
  - 선에는 관계 태그가 없고 카드 위치에 맞춰 좌우 점끼리만 잇습니다. 선을 누르면 `출발 → 도착` 제목과 `연결 해제` · `메모 입력`.
  - 메모는 모두 Enter(또는 `입력 완료`)로 저장하고 `수정`으로 고칩니다. 지시 · 근거 · 의견은 분석에서 AI가 가립니다.
- **자료 검색(오른쪽 사이드바)**: 위 탭 3개, 아래 고정 통합 검색(입력 즉시, Esc로 지움). 항목은 끌어서 캔버스에 놓습니다(두 번 누르면 가운데). 검색창 `+`는 데이터 입력 창(포맷 · 4사 회사 검증).
- **분석**: 세션은 `새로 분석하기`로만 쌓이고 캔버스가 바뀌면 `업데이트`로 같은 세션의 새 버전을 쌓으며(결과는 고치지 않음, 본인만 봄, 휴지통은 목록에서 숨김), 왼쪽 세션 목록에서 지난 세션을 봅니다. 검토(주장과 근거, 캔버스에 표시한 지적, 메모 분류, AI 인사이트, 캔버스 정리 글) · 질문(애널리스트 리포트) · 평가(다음 분기 자료 뒤).
- **동시 편집**: 서버 연동 모드(`VITE_CANVAS_SYNC=server`)에서는 다른 사람의 변경이 바로 반영되고, 다른 사람 커서와 이름, 헤더의 접속자 수가 보입니다. 같은 메모를 다른 사람이 먼저 고쳤으면 최신 글로 바꾸고 안내합니다. 기본은 목업입니다.

## 4. 기능

| 기능 | 하는 법 | 기획서 ID |
|---|---|---|
| 대시보드 · 회사 재무 | 자료 검색 `대시보드` · `회사 재무` 탭. v01-stella DART 대시보드 값(억원). 패널을 끌어 대시보드 카드로 | F-18 |
| 통합 검색 | 아래 검색창에 입력하면 바로 공시 재무 데이터 · IR·AR · 뉴스. `행 고르기`는 원본 표에서 행을 골라 바로 올림 | F-01, F-02 |
| 인사이트 | `인사이트` 탭. 3사 비교(끌면 3사 표 + 비교 카드), 연간 인사이트, 썸네일 뉴스 | F-17, F-02 |
| 데이터 입력 | 검색창 `+` → 파일 선택 · 끌어 놓기. 포맷 불일치 · 회사 불일치(SKT · SKB · KT · LGU+ 밖)는 이유를 보여 주고 막음 | F-03 |
| 표 생성 · 시각화 생성 | Shift로 공시 표 2장 이상 → `표 생성`(비교 카드) · `시각화 생성`(막대 카드). 공통 계정이 없으면 고른 표의 행을 그대로 모음. 비교 카드 ✓ 확정(다시 누르면 취소) · ✗ 거부(대응 없음으로, `되돌리기`) | F-05, F-18 |
| 관계 연결 | 카드의 점(좌우 어느 쪽이든)을 다른 카드로 끌어 연결(관계 태그 없음). 메모 카드는 여러 카드에 연결, Shift 선택 → `메모 연결` | F-06 |
| 메모 | 카드 메모, 카드 `+` → 메모 카드, 하단 `메모`, 선 메모 | F-07 |
| 분석 | 하단 `분석하기` → 검토 → 질문, 평가는 다음 분기 자료 반영 뒤. 지적은 캔버스 박스로 | F-09 ~ F-15, F-17 |
| 페이지 홈 · 협업자 | 로그인하면 페이지 홈. 헤더 정보 아이콘 → 협업자(공유 설정은 소유자만 바꿈) | F-08 (권한 부분), F-19 |

단축키: ⌘K/Ctrl+K로 캔버스 검색창 열기, 검색창 Esc로 검색 지우기, 메모 칸 Enter 저장 · Shift+Enter 줄바꿈, Shift + 클릭 여러 장 선택, Esc로 선택 해제 · 페이지 정보 닫기.

## 5. backend 연결 전 상태

| 지금 (`src/local/`) | backend 연결 후 |
|---|---|
| 페이지와 공유 설정을 localStorage에 저장 (같은 브라우저 안에서만 공유) | 서버 이벤트 저장소, 서버가 권한 검사. 서버 모드(`VITE_CANVAS_SYNC=server`)는 목록·공유·편집·실시간을 모두 서버로(`src/sync/`). 배포 이미지(`Dockerfile`)는 server로 빌드(#179) |
| 분석 세션을 localStorage `telescope-analyses:v1`에 페이지 · 사번별로 저장 | 서버 분석 결과 저장소 (본인만 조회) |
| 다음 분기 자료 도착은 `다음 분기 자료 반영 (데모)` 버튼 | 다음 분기 리포트 수집 뒤 평가 |
| 업로드 검증(포맷 · 4사 회사)은 브라우저(`src/local/validate.ts`) | 업로드 API가 같은 규칙으로 검사 |
| 로그인은 사번 + 아무 비밀번호 | JWT 로그인. 사내 SSO는 이후 확장 |
| 다른 사람 입장은 다른 사번으로 다시 로그인해 확인 | 서버 이벤트 로그로 여러 사람 화면을 맞춤 |
| 검토(메모 분류 · 주장 · 판정 · 지적 · 인사이트) · 질문 · 평가는 규칙 기반 (`src/local/ai.ts`) | ai 서비스(LLM) 호출, 근거 ID 서버 검증 |
| 검색은 bigram BM25 + 개념 사전, 공시 · 문서 검색을 같은 검색어로 함께 부름 | 임베딩 검색 추가 |
| 대시보드 · 회사 재무 값은 `src/local/dart.ts`(v01 공시값) | DuckDB 적재 값을 mcp-server로 조회 |
| 재무 수치·기사·링크, 사내 자료는 팀이 만든 목업. 업로드 본문은 txt·md·csv·json만 읽음 | 수집 파이프라인 자료. 실제 사내 데이터 연동은 MVP 범위 밖 |

화면은 `src/api.ts`의 `api` 객체만 부릅니다. backend를 붙일 때는 이 객체의 구현을 `src/local/` 대신 [API 명세](../docs/frontend/api-spec.md)의 HTTP 호출로 바꿉니다.

판정 규칙(질문 · 가정 · 메모 분류 · 업로드 검증)은 브라우저 콘솔에서 `__aiSelfCheck()`로 점검합니다.

## 6. 로컬 자료 (저장소 루트 `data/demo/`)

원본 자료는 저장소 루트의 `data/demo/`에 둡니다. 루트 `data/`는 git에 올리지 않는 폴더(`.gitkeep`만 올라감)라서 자료는 팀 안에서 따로 주고받습니다.

- **받을 때**: 공유받은 파일을 `data/demo/`에 그대로 넣습니다. 폴더 구조는 아래 표와 같습니다.
- **보낼 때**: 고친 `data/demo/` 폴더를 통째로 압축해 공유합니다.
- **화면만 고칠 때는 필요 없습니다.** 화면은 이 자료를 합친 `frontend/src/local/data.json`(git에 있음)을 씁니다. 그래서 자료가 없어도 `npm run dev`, 빌드, CI·배포가 그대로 돌아갑니다.

```
telescope/
├ data/demo/      ← 공유 자료 (git 제외)
│  ├ manifest.json, *.xml, *.csv, sources.json, analysis.json
│  └ examples/
└ frontend/
   ├ scripts/make_data.py   data/demo → src/local/data.json
   └ src/local/data.json    화면이 쓰는 합친 파일 (git 포함)
```

| 파일 | 내용 |
|---|---|
| `manifest.json` | 어떤 XML·CSV를 어느 회사로 읽을지 |
| `KT_2026Q1.xml` | KT 분기보고서 (DART 원문 XML 형식) |
| `SKT_2026Q1_is.csv`, `SKT_2026Q1_bs.csv` | SKT IR 손익계산서, 재무상태표 |
| `LGU_2026Q1_is.csv` | LGU+ 손익계산서 |
| `SKT·KT·LGU_2026Q1_rp.csv` | 3사 특수관계자 거래 |
| `sources.json` | IR·뉴스 12건, 사내 자료 요약 3건 (요약, 핵심 수치, 개념 태그, 출처 링크) |
| `analysis.json` | 3사 비교 AI 분석, 양식별 가정 계정(`deliverables[].assume`), 질문 뱅크, 평가용 다음 분기(2Q26) 실적과 리포트 쟁점 |
| `examples/` | 예전 백엔드로 낸 기대 결과 (대조용, 이전 목업 회사명 기준) |

질문, 평가 기준은 코드가 아니라 `data/demo/analysis.json`에서 바꿉니다. 2Q26 자료는 평가에서만 쓰고 검토 · 질문에는 넣지 않습니다(시점 통제).

대시보드 · 회사 재무 값(`src/local/dart.ts`)과 썸네일 뉴스(`src/local/news.json`)는 `data/demo/`가 아니라 `frontend/` 안에 있어 git에 함께 올라갑니다.

`data/demo/`를 고쳤을 때는 `src/local/data.json`을 다시 만들고, 바뀐 `data.json`을 커밋합니다. `npm run dev`가 켜져 있으면 새 `data.json`이 화면에 바로 반영됩니다.

```bash
T=<템플릿 위치>/_template/backend
TEMPLATE_BACKEND=$T $T/.venv/bin/python scripts/make_data.py
```

`scripts/make_data.py`는 Python 백엔드 템플릿의 파서(`parse_filing`, `table_from_csv`)와 개념 사전(`concepts.yaml`)을 씁니다. 이 템플릿은 telescope 저장소에 없고 팀 작업 폴더의 `2_frontend/v02-canvas/_template/backend`에 있습니다. `data/demo/`나 템플릿 경로가 없으면 스크립트가 안내 문구를 내고 멈춥니다.
