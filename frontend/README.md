# Telescope 프론트엔드

Telescope 화면입니다. 부서 사람들이 공시·IR·뉴스·사내 자료를 캔버스에 모아 정리하고, 그 근거로 프롬프트·결과물 초안·예상 질문을 만들어 다음 분기 실적으로 평가합니다. 흐름은 [기획서](../docs/planning/기획서.md)를, 화면 구조는 [IA](../docs/frontend/ia.md)를, 서버 API는 [API 명세](../docs/frontend/api-spec.md)를 따릅니다.

- 기술: Vue 3 + TypeScript, Vue Flow(캔버스), Pinia(상태), Vite(개발 서버·빌드), Electron(데스크톱 창)
- 띄우는 곳: 브라우저(`npm run dev`)와 데스크톱 앱(`npm run electron:dev`)
- 지금 상태: backend 연결 전입니다. 서버가 할 일은 `src/local/`이 브라우저 안에서 대신하고, 재무 수치·기사·링크는 팀이 만든 목업 자료입니다(5장, 원본은 6장).

## 1. 실행

`frontend/` 폴더에서 실행합니다. Node 22.18 이상이 필요합니다.

```bash
cd frontend
npm install          # 처음 한 번. Electron 실행 파일도 함께 받음
```

### 1.1 브라우저로 띄우기 (실시간 반영)

```bash
npm run dev
```

터미널에 나오는 `http://localhost:5173`을 브라우저로 엽니다. `src/` 안의 `.vue`·`.ts`·`.css`를 저장하면 새로고침 없이 화면에 바로 반영됩니다(HMR). 끄려면 그 터미널에서 Ctrl+C를 누릅니다.

### 1.2 Electron으로 띄우기

```bash
npm run electron:dev   # 개발 서버 + Electron 창. 코드를 저장하면 창에도 바로 반영
npm run electron       # 배포용 빌드(dist/) 후 그 결과를 Electron 창으로 엶. 서버 없음
```

- `electron:dev`는 Vite 개발 서버와 Electron 창을 같이 띄웁니다. 서버가 뜰 때까지 창이 0.5초마다 다시 연결합니다. 창을 닫아도 개발 서버는 남으니 터미널에서 Ctrl+C로 함께 끕니다.
- 이미 `npm run dev`를 켜 둔 상태라면 `npm run electron:open -- --dev`로 창만 띄웁니다.
- Electron 진입 파일은 `electron/main.cjs`입니다. `package.json`이 ES 모듈 설정이라 CommonJS(`.cjs`)로 둡니다.
- 브라우저, Electron 개발 서버 창, Electron 빌드 창은 저장소(localStorage)가 서로 다릅니다. 한 곳에서 만든 캔버스는 다른 곳에서 보이지 않습니다.

### 1.3 빌드

| 명령 | 결과 | 쓰는 곳 |
|---|---|---|
| `npm run build` | 타입 검사 + `dist/` | 배포(`Dockerfile`의 nginx), `npm run electron` |
| `npm run build:html` | 타입 검사 + `docs/frontend/demo.html` 한 파일 | 기획 문서에 붙이는 공유용. 서버 없이 더블클릭으로 열림 |
| `npm run type-check` | 타입 검사만 | — |

빌드는 상대 경로(`base: './'`)로 나와서 nginx 루트 배포와 Electron 파일 열기에 모두 쓸 수 있습니다.

## 2. 기본 흐름 확인

로그인부터 다시 평가까지 한 번 따라가는 순서입니다.

| 순서 | 할 일 | 보이는 것 |
|---|---|---|
| 1 | 로그인 화면에 미리 들어 있는 계정(사번 `1001`, 이재무, 네트워크센터 · 재무기획)으로 `로그인` → 캔버스 홈에서 `+ 새 캔버스` | 볼 수 있는 캔버스 목록(캔버스 홈), 새 캔버스 |
| 2 | `+ 자료 추가`(⌘K) → 오른쪽 위 `예시 불러오기` | 공시 표 9장, 비교 3장, 시각화 1장, IR·뉴스·사내 자료 4장, 부서장의 보완 요청 메모 1장, 연결 4개 |
| 3 | 자료 추가 화면의 `IR·뉴스` 탭에서 카드를 캔버스로 끌어 놓기 | 캔버스의 회사·개념과 겹치는 IR·뉴스가 먼저 보임 |
| 4 | `사내 자료` 탭에서 txt·md·csv 파일을 끌어 놓기 | 파일에서 뽑은 수치로 요약 카드가 생김 |
| 5 | 비교 카드의 `시각화` | 계정별 회사 막대그래프 카드 |
| 6 | 상단 `공유` → `박망`(1002) 편집 가능, `최예산`(2001) 보기 가능으로 초대. 로그아웃 후 1002로 로그인해 그 캔버스에 메모 추가, 카드끼리 연결. 2001로 로그인하면 `공유받은 캔버스`에서 보기 전용으로 열림 | 왼쪽 `활동 로그`에 박망 이름으로 기록, 보기 권한이면 편집 도구가 없음 |
| 7 | 오른쪽 사이드바 `프롬프트` 탭 → `프롬프트 추출` | 캔버스 카드·메모·연결이 근거 ID가 붙은 프롬프트로 정리됨 |
| 8 | `결과물` 탭 → 결과물 유형 고르고 `초안 생성` | 섹션별 초안. 숫자마다 근거 ID, 근거가 없으면 '근거 부족' |
| 9 | `질문` 탭 → `질문 생성`, `평가` 탭 → 평가 | 예상 질문, 2Q26 리포트 쟁점과 맞은 것·놓친 것, 초안 가정과 실적 차이 |
| 10 | 놓친 쟁점(예: 보안) 관련 자료를 올리고 다시 평가 | 재현율이 바뀜 |

처음부터 다시 보려면 상단 `비우기`를 누르거나 localStorage의 `telescope-canvas:v1`을 지웁니다.

## 3. 화면 구성

```
┌ 탭 줄: 홈 · 지금 캔버스 이름(두 번 눌러 바꾸기) · + 새 캔버스 ──────────────────────┐
├ 상단 바: 로고(홈) · 캔버스 제목 · + 자료 추가 · 메모 · 비우기 · 공유 · 오른쪽 사이드바 ┤
├──────────────┬─────────────────────────────────────┬────────────────────┤
│ 왼쪽 사이드바 │ 캔버스                               │ 오른쪽 사이드바     │
│ 근거 데이터   │  오른쪽 위: 표 비교 · 자동 배치 · 단위 │ 프롬프트 · 결과물   │
│ 활동 로그     │  왼쪽 아래: 선 종류 토글 범례         │ 질문 · 평가        │
│              │  오른쪽 아래: 확대·축소               │ 맨 아래 실행 버튼   │
│ 사용자·로그아웃│                                     │                    │
└──────────────┴─────────────────────────────────────┴────────────────────┘
```

- **로그인**: 사번과 비밀번호를 넣습니다. 지금은 비밀번호를 검사하지 않고, 없는 사번이면 "사번을 확인하세요"가 나옵니다. 사번 `1001`이 미리 입력되어 있습니다. 다른 부서로 보려면 사번을 바꿔 넣습니다(예: 2001 AIDC사업본부, 3001 세일즈마케팅본부, 4001 프로덕트브랜드본부). 들어가면 캔버스 홈이 열립니다.

  | 부서 | 사용자 (직무) |
  |---|---|
  | 네트워크센터 | 이재무 (재무기획), 박망 (네트워크 기술), 김센터 (부서장) |
  | AIDC사업본부 | 최예산 (재무기획), 정데이터 (AIDC 사업), 한본부 (부서장) |
  | 세일즈마케팅본부 | 오마케 (재무기획), 윤영업 (세일즈) |
  | 프로덕트브랜드본부 | 서기획 (재무기획), 강상품 (상품) |

- **캔버스 홈**: Figma 파일 목록처럼 볼 수 있는 캔버스를 타일로 모아 봅니다. 왼쪽 `최근` · `내가 만든 캔버스` · `공유받은 캔버스`로 거르고, 이름으로 검색하고, `+ 새 캔버스`로 만듭니다. 타일에는 카드 배치 미리보기, 수정자 · 시각, 내 권한과 공유 범위가 나옵니다. 소유자는 타일의 ✕로 지웁니다. 캔버스 안에서는 탭 줄 홈 아이콘이나 상단 로고로 돌아옵니다.
- **공유**: 상단 `공유`로 창을 엽니다. 찾기 칸을 누르면 추천 사람(같은 부서 먼저)이 뜨고, 사번 · 이름 · 부서를 입력하면 그 사람을 찾습니다. 골라서 `편집 가능` · `보기 가능`으로 초대하고, 권한을 바꾸거나 지웁니다. `일반 액세스`는 초대한 사람만 / 회사 전체(보기 가능) 중에서 고릅니다. 새 캔버스는 초대한 사람만으로 시작합니다. 보기 권한으로 열면 상단에 `보기 전용`이 나오고 카드를 고칠 수 없지만 오른쪽 사이드바는 씁니다. `✕` · `완료` · Esc로 닫습니다.
- **연관 카드 하이라이트**: 카드를 누르면 그 카드와 선 하나로 이어진 카드(관계선, 비교 원본·시각화, 같은 개념)만 밝게, 나머지 카드와 선은 흐리게 보입니다. 빈 곳을 누르거나 Esc로 해제합니다.
- **선 정리**: 같은 개념 자동 점선은 평소 숨기고, 카드를 골랐을 때 그 카드에 닿는 것만 개념 이름과 함께 보입니다. 비교 원본선은 평소 얇은 회색이고 고른 카드에 닿을 때만 움직입니다. 왼쪽 아래 범례 칩(근거·설명·반박·관련·비교 원본·같은 개념)을 눌러 종류별로 보이기·숨기기를 바꿉니다.
- **왼쪽 사이드바** (항상 열림)
  - `근거 데이터`: 지금 캔버스에 올린 자료를 공시 표, IR·뉴스, 사내 자료, 비교·시각화, 메모로 묶어 보여 줍니다. 유형마다 접고 펼 수 있고, 항목을 누르면 그 카드로 이동합니다.
  - `활동 로그`: 이 캔버스에 권한 있는 사람(권한 표시)과 누가 무엇을 했는지 보여 줍니다.
- **캔버스 카드**: 공시 표, 비교, 시각화, 문서(IR·뉴스·사내 자료), 메모 다섯 종류입니다.
- **오른쪽 사이드바**: 프롬프트 → 결과물 → 질문 → 평가 네 탭입니다. 탭마다 맨 아래 가운데 버튼으로 실행합니다.

## 4. 기능

| 기능 | 하는 법 | 기획서 ID |
|---|---|---|
| 공시 검색 | 자료 추가 → `공시` 탭(처음 열리는 탭)에서 질문을 입력. 문장으로 물어도 회사명과 낱말로 나눠 찾음. `행 고르기`는 원본 표에서 행 선택, `+ 찾은 행 올리기`는 찾은 행만 카드로 올림 | F-01 |
| 3사 비교 AI 분석 | `공시` 탭 위쪽의 분석 카드 3장(수치 증감 + 해석 + 근거 뉴스). `비교 카드로 올리기`를 누르면 3사 공시 표를 올려 비교 카드로 묶음 | F-17 |
| IR·뉴스 | `IR·뉴스` 탭. 위 줄은 IR 자료 원본, 아래 줄은 관련 뉴스. 맨 위 회사 필터. 검색어가 없으면 캔버스의 회사·개념과 많이 겹치는 순 | F-02 |
| 사내 자료 | `사내 자료` 탭. 목록에서 `올리기`, 또는 파일을 끌어 놓아 요약 카드 생성(txt·md·csv만) | F-03 |
| 표 비교 | 공시 표 카드를 2장 이상 체크 → 캔버스 오른쪽 위 `표 비교`. 개념 사전으로 3사 계정을 맞춰 줌 | F-05 |
| 시각화 | 비교 카드의 `시각화`. 계정 칩으로 보일 계정을 고름 | F-18 |
| 메모·보완 요청 | 상단 `메모`. 메모 카드 머리줄에서 `메모 \| 보완 요청`을 고르면 보완 요청은 빨간 테두리로 바뀜 | F-07 |
| 관계 연결 | 카드 오른쪽 점을 다른 카드로 끌면 근거·설명·반박·관련 중 하나로 연결. 같은 개념의 카드는 점선으로 자동 연결(평소 숨김, 카드를 고르거나 범례에서 켜면 표시) | F-06 |
| 캔버스 홈 | 로그인하면 열림. 볼 수 있는 캔버스 전부, 최근 · 내가 만든 · 공유받은 캔버스 | F-08 (권한 부분) |
| 공유 | 상단 `공유`. 추천 · 검색으로 사람 초대(편집 가능 · 보기 가능), 일반 액세스(초대한 사람만 · 회사 전체 보기). 다른 사번으로 다시 로그인하면 그 사람 이름으로 조작이 기록됨 | F-07, F-08 (권한 부분) |
| 프롬프트·초안·질문·평가 | 오른쪽 사이드바 네 탭 | F-09 ~ F-14 |

단축키: ⌘K/Ctrl+K로 자료 추가 열고 닫기, 자료 추가 화면에서 ⌘/Ctrl+1·2·3으로 탭 이동(Tab은 버튼·입력 사이 포커스 이동), Esc로 닫기.

## 5. backend 연결 전 상태

| 지금 (`src/local/`) | backend 연결 후 |
|---|---|
| 캔버스와 공유 설정을 localStorage에 저장 (같은 브라우저 안에서만 공유) | 서버 이벤트 저장소, 서버가 권한 검사 |
| 로그인은 사번 + 아무 비밀번호 | JWT 로그인. 사내 SSO는 이후 확장 |
| 다른 사람 입장은 다른 사번으로 다시 로그인해 확인 | 서버 이벤트 로그로 여러 사람 화면을 맞춤 |
| 초안·질문·평가는 규칙 기반 (`src/local/ai.ts`) | ai 서비스(LLM) 호출 |
| 검색은 bigram BM25 + 개념 사전 | 임베딩 검색 추가 |
| 재무 수치·기사·링크, 사내 자료는 팀이 만든 목업. 업로드는 txt·md·csv만 | 수집 파이프라인 자료. 실제 사내 데이터 연동은 MVP 범위 밖 |

화면은 `src/api.ts`의 `api` 객체만 부릅니다. backend를 붙일 때는 이 객체의 구현을 `src/local/` 대신 [API 명세](../docs/frontend/api-spec.md)의 HTTP 호출로 바꿉니다.

시각화 카드는 화면에만 있고 프롬프트 추출에는 들어가지 않습니다. 판정 규칙은 브라우저 콘솔에서 `__aiSelfCheck()`로 점검합니다.

## 6. 로컬 자료 (저장소 루트 `data/demo/`)

원본 자료는 저장소 루트의 `data/demo/`에 둡니다. 루트 `data/`는 git에 올리지 않는 폴더(`.gitkeep`만 올라감)라서 자료는 팀 안에서 따로 주고받습니다.

- **받을 때**: 공유받은 파일을 `data/demo/`에 그대로 넣습니다. 폴더 구조는 아래 표와 같습니다.
- **보낼 때**: 고친 `data/demo/` 폴더를 통째로 압축해 공유합니다.
- **화면만 고칠 때는 필요 없습니다.** 화면은 이 자료를 합친 `frontend/src/local/data.json`(git에 있음)을 씁니다. 그래서 자료가 없어도 `npm run dev`, 빌드, CI·배포가 그대로 돌아갑니다.

```
telescope/
├ data/demo/      ← 공유 자료 (git 제외)
│  ├ manifest.json, *.xml, *.csv, sources.json, analysis.json
│  └ examples/
└ frontend/
   ├ scripts/make_data.py   data/demo → src/local/data.json
   └ src/local/data.json    화면이 쓰는 합친 파일 (git 포함)
```

| 파일 | 내용 |
|---|---|
| `manifest.json` | 어떤 XML·CSV를 어느 회사로 읽을지 |
| `KT_2026Q1.xml` | KT 분기보고서 (DART 원문 XML 형식) |
| `SKT_2026Q1_is.csv`, `SKT_2026Q1_bs.csv` | SKT IR 손익계산서, 재무상태표 |
| `LGU_2026Q1_is.csv` | LGU+ 손익계산서 |
| `SKT·KT·LGU_2026Q1_rp.csv` | 3사 특수관계자 거래 |
| `sources.json` | IR·뉴스 12건, 사내 자료 요약 3건 (요약, 핵심 수치, 개념 태그, 출처 링크) |
| `analysis.json` | 3사 비교 AI 분석, 결과물 양식(섹션·태그), 질문 뱅크, 평가용 다음 분기(2Q26) 실적과 리포트 쟁점 |
| `examples/` | 예전 백엔드로 낸 기대 결과 (대조용, 이전 목업 회사명 기준) |

결과물 양식, 질문, 평가 기준은 코드가 아니라 `data/demo/analysis.json`에서 바꿉니다. 2Q26 자료는 평가 탭에서만 쓰고 초안·질문 생성에는 넣지 않습니다(시점 통제).

`data/demo/`를 고쳤을 때는 `src/local/data.json`을 다시 만들고, 바뀐 `data.json`을 커밋합니다. `npm run dev`가 켜져 있으면 새 `data.json`이 화면에 바로 반영됩니다.

```bash
T=<템플릿 위치>/_template/backend
TEMPLATE_BACKEND=$T $T/.venv/bin/python scripts/make_data.py
```

`scripts/make_data.py`는 Python 백엔드 템플릿의 파서(`parse_filing`, `table_from_csv`)와 개념 사전(`concepts.yaml`)을 씁니다. 이 템플릿은 telescope 저장소에 없고 팀 작업 폴더의 `2_frontend/v02-canvas/_template/backend`에 있습니다. `data/demo/`나 템플릿 경로가 없으면 스크립트가 안내 문구를 내고 멈춥니다.
