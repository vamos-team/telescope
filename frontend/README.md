# Telescope 프론트엔드

Telescope 화면입니다. 부서 사람들이 공시·IR·뉴스·사내 자료를 캔버스에 모아 정리하고, 카드 · 선 프롬프트와 메모를 붙인 뒤, 캔버스를 근거 ID가 달린 컨텍스트 글로 정리하고 예상 질문을 만들어 다음 분기 실적으로 평가합니다. 흐름은 [기획서](../docs/planning/기획서.md)를, 화면 구조는 [IA](../docs/frontend/ia.md)를, 서버 API는 [API 명세](../docs/frontend/api-spec.md)를 따릅니다.

- 기술: Vue 3 + TypeScript, Vue Flow(캔버스), Pinia(상태), Vite(개발 서버·빌드), Electron(데스크톱 창)
- 띄우는 곳: 브라우저(`npm run dev`)와 데스크톱 앱(`npm run electron:dev`)
- 지금 상태: backend 연결 전입니다. 서버가 할 일은 `src/local/`이 브라우저 안에서 대신하고, 공시 표 · IR · 사내 자료의 수치 · 기사 · 링크는 팀이 만든 목업 자료입니다(5장, 원본은 6장). 자료 검색의 대시보드 · 회사 재무 값과 썸네일 뉴스 13건은 v01-stella 데모에서 가져온 실제 공시값 · 기사입니다(`src/local/dart.ts`, `src/local/news.json`).

## 1. 실행

`frontend/` 폴더에서 실행합니다. Node 22.18 이상이 필요합니다.

```bash
cd frontend
npm install          # 처음 한 번. Electron 실행 파일도 함께 받음
```

### 1.1 브라우저로 띄우기 (실시간 반영)

```bash
npm run dev
```

터미널에 나오는 `http://localhost:5173`을 브라우저로 엽니다. 포트는 5173으로 고정이라, 이미 다른 앱이 쓰고 있으면 서버가 뜨지 않고 멈춥니다(Electron이 같은 주소를 열기 때문). `src/` 안의 `.vue`·`.ts`·`.css`를 저장하면 새로고침 없이 화면에 바로 반영됩니다(HMR). 끄려면 그 터미널에서 Ctrl+C를 누릅니다.

### 1.2 Electron으로 띄우기

```bash
npm run electron:dev   # 개발 서버 + Electron 창. 코드를 저장하면 창에도 바로 반영
npm run electron       # 배포용 빌드(dist/) 후 그 결과를 Electron 창으로 엶. 서버 없음
```

- `electron:dev`는 Vite 개발 서버와 Electron 창을 같이 띄웁니다. 서버가 뜰 때까지 창이 0.5초마다 다시 연결합니다. 창을 닫아도 개발 서버는 남으니 터미널에서 Ctrl+C로 함께 끕니다.
- 이미 `npm run dev`를 켜 둔 상태라면 `npm run electron:open -- --dev`로 창만 띄웁니다.
- Electron 진입 파일은 `electron/main.cjs`입니다. `package.json`이 ES 모듈 설정이라 CommonJS(`.cjs`)로 둡니다.
- 브라우저, Electron 개발 서버 창, Electron 빌드 창은 저장소(localStorage)가 서로 다릅니다. 한 곳에서 만든 캔버스는 다른 곳에서 보이지 않습니다.

### 1.3 빌드

| 명령 | 결과 | 쓰는 곳 |
|---|---|---|
| `npm run build` | 타입 검사 + `dist/` | 배포(`Dockerfile`의 nginx), `npm run electron` |
| `npm run build:html` | 타입 검사 + `docs/frontend/demo.html` 한 파일 | 기획 문서에 붙이는 공유용. 서버 없이 더블클릭으로 열림 |
| `npm run type-check` | 타입 검사만 | — |

빌드는 상대 경로(`base: './'`)로 나와서 nginx 루트 배포와 Electron 파일 열기에 모두 쓸 수 있습니다.

## 3. 화면 구성

```
┌ 상단 바: 로고(메뉴) · 캔버스 제목(두 번 눌러 바꾸기) · 분기 ··········· 자료 검색 · 메모 · 생성하기 ┐
├──────────────┬─────────────────────────────────────┬─────────────────────────────┤
│ 왼쪽 사이드바 │ 캔버스                               │ 오른쪽 결과 패널 (생성하기 뒤) │
│ 근거 데이터   │  오른쪽 위: 자동 배치 · 비우기 · 단위  │ » 접기 · 다시 생성            │
│ 프롬프트      │  왼쪽 아래: 선 종류 토글 범례         │ 프로세스 바: 생성─질문─평가   │
│              │  오른쪽 아래: 확대·축소               │ 정리 글 / 질문 / 평가          │
│ 사용자·로그아웃│                                     │                             │
└──────────────┴─────────────────────────────────────┴─────────────────────────────┘
```

- **로그인**: 사번과 비밀번호를 넣습니다. 지금은 비밀번호를 검사하지 않고, 없는 사번이면 "사번을 확인하세요"가 나옵니다. 사번 `1001`이 미리 입력되어 있습니다. 다른 부서로 보려면 사번을 바꿔 넣습니다(예: 2001 AIDC사업본부, 3001 세일즈마케팅본부, 4001 프로덕트브랜드본부). 들어가면 캔버스 홈이 열립니다.

  | 부서 | 사용자 (직무) |
  |---|---|
  | 네트워크센터 | 이재무 (재무기획), 박망 (네트워크 기술), 김센터 (부서장) |
  | AIDC사업본부 | 최예산 (재무기획), 정데이터 (AIDC 사업), 한본부 (부서장) |
  | 세일즈마케팅본부 | 오마케 (재무기획), 윤영업 (세일즈) |
  | 프로덕트브랜드본부 | 서기획 (재무기획), 강상품 (상품) |

- **캔버스 홈**: Figma 파일 목록처럼 볼 수 있는 캔버스를 타일로 모아 봅니다. 왼쪽 `최근` · `내가 만든 캔버스` · `공유받은 캔버스`로 거르고, 이름으로 검색하고, `+ 새 캔버스`로 이름 · 분기 · 편집할 사람을 정해 만듭니다. 소유자는 타일의 ✕로 지웁니다.
- **메뉴 · 공유**: 캔버스 안에서 로고를 누르면 왼쪽 팝업(홈 · 나의 캔버스, 지금 캔버스 정보)이 열리고, `정보 수정`으로 공유 창을 엽니다. 공유 창에서 사람을 `편집 가능` · `보기 가능`으로 초대합니다. 공유 설정은 소유자만 바꿀 수 있고, 편집 · 보기 권한으로 열면 공유 창이 읽기 전용입니다. 캔버스는 소유자와 초대한 사람만 볼 수 있습니다. 보기 권한이면 상단에 `보기 전용`이 나오고 카드를 고칠 수 없지만 생성하기는 씁니다.
- **자료 검색**(상단 `자료 검색`, ⌘K): 흰 전체 화면. 입력이 비면 하단 탭 `대시보드` · `회사 재무` · `인사이트`, 입력하면 통합 검색 결과. 누르면 선택 칩, 입력창 오른쪽 `추가하기`로 올림, 길게 누르면 그 항목만 끌어 놓음. 입력창 왼쪽 `+`는 사내 자료 첨부.
- **연관 카드 하이라이트**: 카드를 누르면 그 카드와 선 하나로 이어진 카드만 밝게, 나머지는 흐리게 보이고 카드 프롬프트 칸이 펼쳐집니다. 빈 곳을 누르거나 Esc로 해제합니다.
- **선 정리**: 같은 개념 자동 점선은 평소 숨기고, 카드를 골랐을 때 그 카드에 닿는 것만 보입니다. 왼쪽 아래 범례 칩으로 종류별 보이기 · 숨기기를 바꿉니다.
- **왼쪽 사이드바**
  - `근거 데이터`: 캔버스에 올린 자료를 공시 표, IR·AR, 뉴스, 사내 자료, 비교·시각화, 메모로 묶어 보여 줍니다. 항목을 누르면 그 카드로 이동합니다.
  - `프롬프트`: 카드 프롬프트 · 선 프롬프트 목록. 누르면 그 카드나 선으로 이동합니다.
- **캔버스 카드**: 공시 표, 비교, 시각화, 대시보드, 문서(IR·AR·뉴스·사내 자료, 뉴스는 썸네일), 메모 여섯 종류입니다. 메모를 뺀 카드에는 카드 프롬프트 칸이 붙습니다.
- **오른쪽 결과 패널**: `생성하기`로 열리고 화면 절반을 씁니다. 가로 프로세스 바의 끝난 단계를 눌러 정리 글 · 질문 · 평가를 오갑니다. `»`로 접고 `«`로 폅니다.

## 4. 기능

| 기능 | 하는 법 | 기획서 ID |
|---|---|---|
| 대시보드 · 회사 재무 | 자료 검색의 `대시보드` · `회사 재무` 탭. v01-stella DART 대시보드 값(억원)으로 KPI · 워터폴 · 산점도 · 히트맵 · 자산 계정(히트맵 · 자산 맵 · 표, 근거 패널)과 손익(연간/분기) · 재무상태 · 현금흐름 · 설비투자 · 동종사 비교. 패널마다 담기 · 끌기 | F-18 |
| 통합 검색 | 입력창에 입력하면 바로 공시 재무 데이터 · IR·AR · 뉴스 결과. 문장으로 물어도 회사명과 낱말로 나눠 찾음. 재무 행 `행 고르기`는 원본 표에서 행 선택 | F-01, F-02 |
| 인사이트 | `인사이트` 탭. 3사 비교(분기, 담으면 3사 표 + 비교 카드), 연간 인사이트(담으면 대시보드 카드), 썸네일 뉴스(회사 필터, 캔버스의 회사 · 개념과 겹치는 순) | F-17, F-02 |
| 사내 자료 | 입력창 왼쪽 `+`로 파일 선택(txt·md·csv만 본문 요약) → 선택 칩 | F-03 |
| 표 비교 · 시각화 | 인사이트의 3사 비교를 담으면 비교 카드가 생김. 비교 카드의 `시각화`로 막대그래프 카드 | F-05, F-18 |
| 관계 연결 | 카드 오른쪽 점을 다른 카드로 끌어 근거 · 설명 · 반박 · 관련으로 연결. 같은 개념은 점선으로 자동 연결 | F-06 |
| 메모 · 프롬프트 | 상단 `메모`(메모 / 보완 요청). 카드를 눌러 카드 프롬프트, 선을 눌러 선 프롬프트 | F-07 |
| 생성하기 | 상단 `생성하기` → 캔버스 정리 글(편집 · 복사 · Markdown) → 질문(Markdown) → 평가 | F-09 ~ F-14 |
| 캔버스 홈 · 공유 | 로그인하면 캔버스 홈. 로고 → 정보 수정 → 공유 창 | F-08 (권한 부분), F-19 |

단축키: ⌘K/Ctrl+K로 자료 검색 열고 닫기, 자료 검색에서 입력이 비었을 때 Tab · Shift+Tab으로 탭 이동(대시보드 → 회사 재무 → 인사이트), Esc로 닫기.

## 5. backend 연결 전 상태

| 지금 (`src/local/`) | backend 연결 후 |
|---|---|
| 캔버스와 공유 설정을 localStorage에 저장 (같은 브라우저 안에서만 공유) | 서버 이벤트 저장소, 서버가 권한 검사 |
| 로그인은 사번 + 아무 비밀번호 | JWT 로그인. 사내 SSO는 이후 확장 |
| 다른 사람 입장은 다른 사번으로 다시 로그인해 확인 | 서버 이벤트 로그로 여러 사람 화면을 맞춤 |
| 정리 글 · 질문 · 평가는 규칙 기반 (`src/local/ai.ts`) | ai 서비스(LLM) 호출 |
| 검색은 bigram BM25 + 개념 사전, 공시 · 문서 검색을 같은 검색어로 함께 부름 | 임베딩 검색 추가 |
| 대시보드 · 회사 재무 값은 `src/local/dart.ts`(v01 공시값) | DuckDB 적재 값을 mcp-server로 조회 |
| 재무 수치·기사·링크, 사내 자료는 팀이 만든 목업. 업로드는 txt·md·csv만 | 수집 파이프라인 자료. 실제 사내 데이터 연동은 MVP 범위 밖 |

화면은 `src/api.ts`의 `api` 객체만 부릅니다. backend를 붙일 때는 이 객체의 구현을 `src/local/` 대신 [API 명세](../docs/frontend/api-spec.md)의 HTTP 호출로 바꿉니다.

시각화 카드는 화면에만 있고 컨텍스트에는 카드 프롬프트만 들어갑니다. 판정 규칙은 브라우저 콘솔에서 `__aiSelfCheck()`로 점검합니다.

## 6. 로컬 자료 (저장소 루트 `data/demo/`)

원본 자료는 저장소 루트의 `data/demo/`에 둡니다. 루트 `data/`는 git에 올리지 않는 폴더(`.gitkeep`만 올라감)라서 자료는 팀 안에서 따로 주고받습니다.

- **받을 때**: 공유받은 파일을 `data/demo/`에 그대로 넣습니다. 폴더 구조는 아래 표와 같습니다.
- **보낼 때**: 고친 `data/demo/` 폴더를 통째로 압축해 공유합니다.
- **화면만 고칠 때는 필요 없습니다.** 화면은 이 자료를 합친 `frontend/src/local/data.json`(git에 있음)을 씁니다. 그래서 자료가 없어도 `npm run dev`, 빌드, CI·배포가 그대로 돌아갑니다.

```
telescope/
├ data/demo/      ← 공유 자료 (git 제외)
│  ├ manifest.json, *.xml, *.csv, sources.json, analysis.json
│  └ examples/
└ frontend/
   ├ scripts/make_data.py   data/demo → src/local/data.json
   └ src/local/data.json    화면이 쓰는 합친 파일 (git 포함)
```

| 파일 | 내용 |
|---|---|
| `manifest.json` | 어떤 XML·CSV를 어느 회사로 읽을지 |
| `KT_2026Q1.xml` | KT 분기보고서 (DART 원문 XML 형식) |
| `SKT_2026Q1_is.csv`, `SKT_2026Q1_bs.csv` | SKT IR 손익계산서, 재무상태표 |
| `LGU_2026Q1_is.csv` | LGU+ 손익계산서 |
| `SKT·KT·LGU_2026Q1_rp.csv` | 3사 특수관계자 거래 |
| `sources.json` | IR·뉴스 12건, 사내 자료 요약 3건 (요약, 핵심 수치, 개념 태그, 출처 링크) |
| `analysis.json` | 3사 비교 AI 분석, 양식별 가정 계정(`deliverables[].assume`), 질문 뱅크, 평가용 다음 분기(2Q26) 실적과 리포트 쟁점 |
| `examples/` | 예전 백엔드로 낸 기대 결과 (대조용, 이전 목업 회사명 기준) |

질문, 평가 기준은 코드가 아니라 `data/demo/analysis.json`에서 바꿉니다. 2Q26 자료는 평가에서만 쓰고 정리 글 · 질문 생성에는 넣지 않습니다(시점 통제).

대시보드 · 회사 재무 값(`src/local/dart.ts`)과 썸네일 뉴스(`src/local/news.json`)는 `data/demo/`가 아니라 `frontend/` 안에 있어 git에 함께 올라갑니다.

`data/demo/`를 고쳤을 때는 `src/local/data.json`을 다시 만들고, 바뀐 `data.json`을 커밋합니다. `npm run dev`가 켜져 있으면 새 `data.json`이 화면에 바로 반영됩니다.

```bash
T=<템플릿 위치>/_template/backend
TEMPLATE_BACKEND=$T $T/.venv/bin/python scripts/make_data.py
```

`scripts/make_data.py`는 Python 백엔드 템플릿의 파서(`parse_filing`, `table_from_csv`)와 개념 사전(`concepts.yaml`)을 씁니다. 이 템플릿은 telescope 저장소에 없고 팀 작업 폴더의 `2_frontend/v02-canvas/_template/backend`에 있습니다. `data/demo/`나 템플릿 경로가 없으면 스크립트가 안내 문구를 내고 멈춥니다.
