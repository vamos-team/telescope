# 부서별 예산서 검토 포인트 (검토 기준 초안)

> 검토 기준은 **항상 애널리스트 관점**이에요. 사용자가 B10에서 **부서**를 고르면, AI는 그 부서가 낸 예산서에서 검토자가 주로 묻는 포인트를 더 엄격하게 봐요.
> 이 문서는 추후 Agent(예산서 검토 에이전트)의 시스템 프롬프트와 점검 항목을 만들 때 참고해요.
> 공개 자료로 정리한 일반 관행이에요. SKT 실제 부서명과 사내 양식은 현업 멘토링에서 확인해야 해요.

## 1. 공통 점검 항목 (모든 부서)

`예산 검토 업무.md`(팀 기획 자료) 4장에서 가져와요.

| 점검 항목 | 근거 충분으로 보는 조건 |
|---|---|
| 산출 근거 | 금액이 단가 × 수량, 인원 × 단가로 나뉘어 있음 |
| 전년 대비 증감 | 증감 사유가 숫자와 함께 있음 |
| 집행률 | 올해 계획 대비 실적이 있음 |
| 전략 연결 | 경영방침, 핵심 과제와 잇는 문장이 있음 |
| 필요성과 대안 | 안 할 때 영향, 대안 비교가 있음 |
| 투자 효과 | 회수 시점과 규모가 있음 |
| 재무 영향 | 감가상각, 영업이익 영향이 있음 |

## 2. 부서 목록과 집중 포인트

부서를 고르면 아래 **집중 포인트**를 점검 항목보다 앞에 두고, 해당 지표가 없으면 근거 부족으로 표시해요.

| # | 부서 | 예산서에 주로 담기는 것 | 집중 포인트 (AI가 더 엄격하게 보는 것) | 공시 데이터로 대조할 지표 (DART 적재) |
|---|---|---|---|---|
| 1 | 네트워크/인프라 (Infra/Tech) | 기지국, 전송망, 데이터센터 CapEx, 유지보수비 | 신규 투자와 유지·교체 투자 구분, 장비 단가 × 수량, 감가상각 일정, 품질 지표(커버리지, 속도)로 감액 사유 뒷받침 | CapEx, 감가상각비, 유형자산 |
| 2 | 마케팅 | 광고, 판매 수수료, 단말 지원금, 캠페인 | 매출 대비 마케팅비 비율, 가입자 획득 비용, ARPU와 해지율 변화, 캠페인별 성과 측정 방법 | 매출, 판매비와관리비 |
| 3 | AI/신사업 | AI 데이터센터, GPUaaS, 신규 서비스 개발 | 매출 회수 시점, 고객 수와 가동률 가정, 시장 규모 가정의 출처, 단계별 투자 중단 기준 | CapEx, 신규 사업 매출 |
| 4 | IT/정보시스템 | 라이선스, 클라우드, 시스템 구축, 외부 용역 | 유지 계약의 계속 필요 여부, 중복 시스템, 클라우드 사용량 근거, 보안·규제 대응 여부 | 판매비와관리비, 무형자산 |
| 5 | 연구개발 (R&D) | 과제별 연구비, 시험 장비, 외부 협력 | 과제별 마일스톤과 일정 지연, 유사·중복 과제, 사업화 계획 | 연구개발비 |
| 6 | 인사/경영지원 | 인건비, 채용, 교육, 복리후생 | 인원 계획과 채용 시점, 인당 인건비 증가율, 교육비 효과 | 급여, 종업원 수 |
| 7 | 영업/B2B | 기업 고객 영업비, 제안 비용, 파트너 수수료 | 수주 파이프라인과 매출 목표 연결, 고객별 수익성 | 매출 (부문별) |
| 8 | 재무/경영기획 (본사 공통) | 공통비, 주주환원, 차입 | 공통비 배부 기준, 주주환원 재원, 부채비율 영향 | 부채, 자본, 배당 |

- **MVP 데모 부서:** 1 네트워크/인프라. 데모 예산서(SKT 2025 사업보고서 II-3 설비투자 절)와 맞아요.
- 나머지 부서는 토글 목록에 보여 주고, 집중 포인트는 이 표를 프롬프트로 넣는 데까지만 구현해요 (범용 설정 = should).

## 3. Agent 구성 때 쓰는 법

```
시스템 프롬프트 = 애널리스트 검토자 역할
               + 공통 점검 항목 (1장)
               + 선택한 부서의 집중 포인트 (2장 한 행)
               + 회사, 분기 (B10 토글)
```

- 부서별로 Agent를 따로 만들지 않고, 같은 Agent에 부서 행만 바꿔 넣어요.
- 부서별 집중 포인트는 현업 인터뷰 뒤 이 표를 고치면 코드 수정 없이 반영돼요.

## 4. 현업에 확인할 것

- SKT 실제 예산 제출 단위(부서명, 조직 단위)가 이 목록과 맞는지
- 부서별로 검토 부서가 실제 가장 자주 되돌려 보내는 사유
- 부서마다 정해진 예산서 양식이 있는지 (입력 자료 종류 설정과 연결)
