# API 규약 (backend)

> 작성자 : 윤혜정 (이슈 #36)

> 화면이 부르는 API의 **경로와 필드는 `docs/frontend/api-spec.md`**(프론트 API 명세)를 기준으로 한다.
> 이 문서는 그 API들이 공통으로 따르는 backend 규약을 다룬다: 응답 형식, 에러 코드, 인증·사용자,
> 캔버스 권한, 동시 편집 저장 규칙, API별 구현 담당, 작업 상태.
>
> - 표시: **[현재]** 코드에 이미 있는 동작, **[제안]** 아직 코드가 없거나 팀 결정 전인 내용. 결정되면 [현재]로 바꾸고 10장에서 지운다.
> - 프론트 명세와 이 문서가 다르면 이 문서의 규약을 따르고, 프론트 명세를 맞춰 고친다.
> - `CLAUDE.md` 7장의 미정 항목은 여기서 정하지 않는다.

## 1. 공통

### 1.1 규칙

| 항목 | 규칙 | 상태 |
|---|---|---|
| 기본 경로 | `/api/v1`. 리소스는 명사 복수형 | [현재] |
| 본문 | JSON, UTF-8. 파일 업로드만 `multipart/form-data` | [현재] |
| 필드 이름 | camelCase | [현재] |
| 인증 | 로그인으로 받은 토큰을 `Authorization: Bearer {accessToken}`으로 보낸다. 로그인·`/actuator/health` 외 모든 API에 필요 | [제안] #34 |
| 시각 | ISO 8601, 시간대 표기 없음, 한국 시간(배포 파드 `TZ=Asia/Seoul`): `"2026-11-25T09:30:00"`. 날짜만은 `"2026-11-25"` | [현재] |
| 금액 단위 | 원본 표는 공시 단위 그대로. 비교·근거 값의 십억원 변환은 코드가 한다(LLM에 맡기지 않음, `CLAUDE.md` 4번) | [제안] |
| 기준 시점·허용 자료 | 초안·질문·평가처럼 예측에 쓰는 요청은 `asOfDate`가 필수다. backend가 허용 자료를 정해 ai·mcp-server에 넘기고, 필터 결과가 비어도 전체 자료로 넘어가지 않는다 | [제안] |
| 결과 보존 | 초안·질문·평가 결과는 고치지 않고 새로 쌓는다 | [제안] |

### 1.2 응답 형식 (`ApiResponse`) [현재]

성공이면 `error`가 `null`, 실패면 `data`가 `null`이다. 최상위에 `status`, `message` 필드는 없다.

```json
{ "data": { "id": 42 }, "error": null }
```

```json
{ "data": null, "error": { "code": "C002", "message": "ID 42번 작업을 찾을 수 없습니다." } }
```

- 화면은 `error.code`로 분기한다. `error.message`는 표시용이며 같은 코드라도 문구가 구체적으로 바뀔 수 있다.
- 에러 응답에 화면이 다시 그릴 데이터가 필요하면 `data`에 담는다(예: 메모 충돌 시 현재 메모, 5.3).

### 1.3 목록 (`PageResponse`) [현재 응답 형식, 요청 파라미터는 제안]

페이지가 필요한 목록은 `data`에 `{ content, page, size, totalElements, totalPages, hasNext }`를 담는다. `page`는 0부터 시작한다.
요청 파라미터는 `?page=0&size=20`(기본 20, 최대 100)을 제안한다. 활동 로그처럼 개수가 정해진 목록은 배열을 그대로 담는다.

## 3. 인증·사용자 [제안] (#34)

### 3.1 사용자 필드 (`User`)

| 필드 | 설명 | 타입 |
|---|---|---|
| `id` | 사용자 ID. 숫자 PK. API 경로·요청에서 사람을 가리킬 때는 이 값을 쓴다 | number |
| `employeeNo` | 사번. 로그인과 검색·표시에만 쓴다 | string |
| `name` | 이름 | string |
| `dept` | 부서. 표시용이며 권한에 쓰지 않는다 | string |
| `job` | 직무 (예: 재무기획, 부서장). 표시용 | string |
| `role` | 서비스 전체 역할 `ADMIN` / `USER`. 공용 문서 수집·삭제는 `ADMIN`만 | string |

- 사번을 ID로 쓰지 않는 이유: 사번은 사람이 읽는 업무 값이라 바뀌거나 형식이 달라질 수 있고, 다른 테이블이 참조하는 키는 바뀌지 않아야 한다.
- 비밀번호 해시는 어떤 응답에도 담지 않는다.
- users 테이블(V2)에 `employee_no`(고유), `dept`, `job` 컬럼이 필요하다. `login_id`는 사번으로 대체한다. 새 마이그레이션으로 처리한다(#34).

### 3.2 규칙

- 로그인은 사번 + 비밀번호(`POST /api/v1/auth/login`). 응답은 `{ accessToken, tokenType: "Bearer", expiresIn, user }`.
- 로그아웃은 서버 호출 없이 토큰을 버린다.
- 사용자 검색(`GET /api/v1/users?q=`)은 사번·이름·부서 일부로 찾는다. 응답에 `role`은 담지 않는다.

| 상황 | HTTP | 코드 |
|---|---|---|
| 사번 없음, 비밀번호 불일치 | 401 | `A001` |
| `Authorization` 헤더 없음, `Bearer` 형식 아님, 서명 위조 | 401 | `A002` |
| 토큰 만료 | 401 | `A003` |
| 관리자 전용 기능을 `USER`가 호출 | 403 | `A004` |

## 4. 캔버스 권한 [제안] (#82)

캔버스마다 **소유자**(만든 사람) 한 명이 있고, 소유자가 다른 사용자를 **편집** 또는 **보기**로 초대한다. 부서는 권한에 쓰지 않는다.
일반 액세스(회사 전체 공개)는 두지 않는다. 캔버스는 소유자와 직접 초대받은 사람만 볼 수 있다.

| 기능 | 소유자 | 편집 | 보기 | 권한 없음 |
|---|---|---|---|---|
| 캔버스 열기, 활동 로그, 비교·근거·프롬프트 조회, 공유 명단 보기 | ○ | ○ | ○ | `K001` |
| 카드·연결 조작 (`events`) | ○ | ○ | `K002` | `K001` |
| 초안·질문 생성, 평가 | ○ | ○ | `K002` | `K001` |
| 이름 변경 | ○ | ○ | `K002` | `K001` |
| 삭제 | ○ | `K002` | `K002` | `K001` |
| **공유 설정 변경 (초대·권한 변경·내보내기)** | ○ | `K002` | `K002` | `K001` |

- 초대는 수락 단계 없이 바로 반영된다.
- 소유자는 한 명이며 권한을 바꾸거나 내보낼 수 없다. 소유권 넘기기는 MVP 범위 밖이다.
- 권한은 HTTP 요청과 실시간 구독 모두에서 서버가 확인한다. 공유가 풀린 사람은 다음 요청부터 `K001`을 받고, 열어 둔 실시간 구독도 끊긴다.
- 공유 설정 변경과 그 결과는 활동 로그에 남는다.
- 캔버스 목록은 내가 소유했거나 초대받은 캔버스다. 각 항목에 내 권한(`owner` / `edit` / `view`)을 담는다.
- 삭제는 목록에서 숨기는 방식(삭제 표시)을 제안한다. 그 캔버스로 만든 초안·질문·평가 결과는 남는다.

## 5. 캔버스 동시 편집 저장 규칙 [제안] (#82, #83)

여러 사람이 같은 캔버스를 동시에 고쳐도 변경이 사라지지 않게 하는 규칙이다. backend와 화면의 서버 연동 계층에 함께 적용한다.

### 5.1 ID

- 카드·연결 ID는 화면이 **UUID**로 만든다. 여러 사람이 동시에 만들어도 겹치지 않는다(데모의 `c{n}`, `l{n}` 순번은 쓰지 않는다).
- 캔버스 ID는 서버가 발급하는 숫자다.

### 5.2 이벤트 묶음 (`POST /api/v1/canvases/{id}/events`)

| 요청 필드 | 설명 |
|---|---|
| `requestId` | 묶음마다 화면이 만드는 UUID. 같은 묶음을 다시 보낼 때는 **같은 값** |
| `events` | 이벤트 목록 (종류는 프론트 명세). 작성자는 토큰의 사용자이며 요청 값을 쓰지 않는다 |

| 응답 필드 | 설명 |
|---|---|
| `lastSeq` | 반영 후 마지막 이벤트 번호 |
| `firstChangedLayer` | 처음 바뀐 컨텍스트 층 |
| `memoVersions` | 이번 묶음으로 바뀐 메모의 새 버전 `{ cardId: version }` |

- 한 묶음은 한 트랜잭션이다. 카드 상태 변경과 이벤트 로그를 같이 저장하고, 하나라도 실패하면 묶음 전체를 반영하지 않는다.
- 이벤트 번호(`seq`)는 캔버스 단위로 1씩 늘어난다. 같은 캔버스의 묶음은 순서대로 저장한다(캔버스 행 잠금).
- 같은 `requestId`가 다시 오면 저장하지 않고 처음 응답을 그대로 돌려준다(전송 실패 후 재전송 대비).

### 5.3 같은 카드를 동시에 고칠 때

- 위치(`move_card`)와 메모 본문(`edit_memo`)은 다른 필드라 서로 덮어쓰지 않는다. 한 사람이 카드를 옮기는 동안 다른 사람이 메모를 고쳐도 둘 다 남는다.
- 위치는 나중에 저장된 값이 이긴다.
- 메모 카드는 `memoVersion`을 갖고, 본문이 바뀔 때마다 1씩 오른다. `edit_memo`는 고치기 시작한 시점의 버전을 `baseVersion`으로 보낸다.
  현재 버전과 다르면 묶음 전체를 `409 K003`으로 거절하고, `data`에 현재 메모 `{ cardId, text, memoVersion }`를 담는다.
  화면은 최신 메모를 보여 주고 다시 고치게 하며, 나머지 이벤트는 새 `requestId`로 다시 보낸다.

### 5.4 다른 사람의 변경 받기와 복원

- 커밋된 변경만 다른 멤버에게 보낸다. 롤백된 묶음은 보내지 않는다.
- 받는 쪽은 `seq`가 이어지는지 확인하고, 빠진 번호가 있거나 재접속하면 캔버스 전체를 다시 조회한다(`GET /api/v1/canvases/{id}`의 `lastSeq` 기준).
- 전달 방식(WebSocket 구독 vs `GET /canvases/{id}/events?after={seq}` 폴링)은 10장 미정 항목이다.
- 캔버스를 열 때 일부 카드를 복원하지 못해도(가리키는 표·문서가 사라짐) `200`으로 나머지를 돌려주고 `warnings[]`에 이유를 담는다. 조회 실패(409)로 처리하지 않는다.
- 상태는 서버에 저장되므로 새로고침·재접속·서버 재시작 뒤에도 같은 상태로 열린다.

## 6. 구현 담당

화면은 backend만 부른다. backend가 인증·캔버스 권한·기준 시점을 확인한 뒤 필요한 곳을 대신 부른다.
DuckDB·ChromaDB는 backend가 직접 열지 않는다(`CLAUDE.md` 3번).

| 표시 | 뜻 |
|---|---|
| BE | backend가 PostgreSQL로 직접 처리 |
| MCP | backend → `mcp-server/http` 동기 호출 (DuckDB·ChromaDB 조회) |
| AI동기 | backend → ai/server 동기 API (빠른 계산) |
| AI작업 | backend → ai/server 작업(202 + 폴링) |

| API (프론트 명세) | 담당 |
|---|---|
| 로그인, 내 정보, 사용자 검색 | BE |
| 캔버스 목록·생성·이름 변경·삭제, 열기 | BE |
| 공유 명단 조회·변경 | BE |
| 이벤트, 활동 로그, 다른 사람 변경 받기 | BE |
| 카드 태그 | AI동기 |
| 공시 검색, 공시 표 조회, 주석 표 찾기 | MCP |
| 3사 비교 AI 분석 (`insights`) | AI동기 |
| 자료 검색 대시보드 (`dashboard`) | MCP (재무 수치 조회, 비율은 backend 코드로 계산) |
| 문서 검색·추천, 문서 단건 | MCP |
| 사내 자료 업로드 | AI작업 (자료 준비) |
| 표 비교 | AI동기 |
| 결과물 양식 (`deliverables`) | BE (10장) |
| 프롬프트 추출, 근거 목록 | AI동기 |
| 초안 생성, 질문 생성 | AI작업 |
| 평가 | 10장 미정 |
| 작업 상태 | BE |

- `mcp-server/http`의 담당 범위와 조회 함수 규약, ai/server 동기 API 규약은 ai 담당자와 확정한다(10장).
- 공시·문서 같은 공용 자료는 로그인 사용자 모두 조회한다. 캔버스 맥락의 조회(추천, 비교 등)는 캔버스 권한을 먼저 확인한다.

## 7. 작업

> 상세 규칙은 `docs/backend/job.md`.

### 7.1 작업 시작 응답 [제안]

오래 걸리는 작업을 시작하는 API(사내 자료 업로드, 초안, 질문)는 `202`와 함께 `data.jobId`(backend가 발급한 `Job.id`)와 대상 ID(`documentIds`, `draftId`, `questionSetId`)를 돌려준다.
ai 서비스가 발급한 ID(`externalJobId`)는 화면에 노출하지 않는다. 결과는 작업 상태에 담지 않고, `SUCCEEDED`가 되면 대상 조회 API로 가져온다.

### 7.2 `GET /api/v1/jobs/{id}` [현재]

| 응답 `data` | 설명 | 타입 |
|---|---|---|
| `id` | 작업 ID | number |
| `jobType` | `DOCUMENT_PREPARATION` / `ANALYSIS` / `PREDICTION` | string |
| `status` | `QUEUED` / `RUNNING` / `SUCCEEDED` / `FAILED` | string |
| `startedAt` | 시작 시각. 시작 전이면 `null` | string \| null |
| `finishedAt` | 종료 시각. 끝나지 않았으면 `null` | string \| null |
| `errorMessage` | 실패 사유. `FAILED`가 아니면 `null` | string \| null |

```json
{
  "data": { "id": 42, "jobType": "ANALYSIS", "status": "RUNNING", "startedAt": "2026-11-25T09:30:00", "finishedAt": null, "errorMessage": null },
  "error": null
}
```

| HTTP | 코드 | 상황 |
|---|---|---|
| 400 | `C001` | `id`가 숫자가 아님 |
| 404 | `C002` | 없는 작업 |

- ai 호출이 일시적으로 실패해도 에러를 내지 않고 마지막 저장 상태를 돌려준다(`job.md` 3.3).
- 지금은 인증 없이 열려 있다. #34 이후 인증이 필요하다.

## 9. 프론트 명세에 반영할 것

이 문서의 규약 중 `docs/frontend/api-spec.md`와 다른 부분이다. 프론트 담당자와 맞춘 뒤 프론트 명세를 고친다.

| 에러 코드 | HTTP 상태만 | 2장 코드 |
