# 사내업무혁신 11. 기업 경영실적 다면/심층 분석 AI Agent

> 통신 3사의 IR 자료, 사업보고서, 공시 재무 데이터를 함께 읽어 회사의 주장마다 받쳐 줄 숫자가 있는지 점검하고, 애널리스트가 던질 질문을 근거 위치와 함께 예측하는 Agent를 만들어요. 예측은 그 뒤에 나온 애널리스트 리포트의 쟁점과 견줘 평가하고, 설정만 바꾸면 사내 예산서 검토에도 쓸 수 있게 해요.

| 기술 난이도 | 작업량 | 그룹사 | 주관 부서       | 핵심 기술     |
| ------ | --- | --- | ----------- | --------- |
| 상      | 중   | SKT | Infra/Tech팀 | #데이터 #RAG |

## 1. 왜 필요한가요?

기업은 IR 자료와 사업보고서로 실적과 투자계획을 밝혀요. 애널리스트는 이를 읽고 질문과 쟁점을 리포트로 내요. 이 자료를 분석할 때는 이런 어려움이 있어요.

- 자료가 여러 형태로 흩어져 있어요. IR 자료, 사업보고서, 재무 데이터를 함께 봐야 해요.
- 주장과 숫자를 맞춰 보기 어려워요. 회사의 주장마다 받쳐 줄 숫자가 있는지 하나씩 확인해야 해요.
- 시장의 질문을 미리 알기 어려워요. 어떤 쟁점이 나올지는 리포트가 나와야 알아요.

그래서 기업 자료를 함께 분석해 근거가 약한 곳을 짚고, 애널리스트가 던질 질문을 예측하는 Agent를 만들어요. 예측이 맞았는지는 이후에 나온 리포트와 견줘 확인해요.
최종 목표는 사내 예산 검토예요. 구성원은 예산서와 근거 자료를 검토 부서에 내요. 그런데 검토자가 무엇을 물을지 미리 알기 어려워 보완하느라 여러 번 오가요. 이 Agent가 내기 전에 검토자의 눈으로 먼저 읽어 주면 이런 왕복을 줄일 수 있어요.
실제 예산서와 검토 의견은 사내 기밀이에요. 그래서 구조가 닮은 공개 데이터로 먼저 만들고 검증해요.

| 최종 활용 업무         | 이번 과제에서 쓰는 공개 데이터         |
| ---------------- | ------------------------- |
| 예산서와 근거 자료       | 기업 IR 자료, 사업보고서           |
| 예산의 정량 근거        | CapEx, 감가상각 등 공시 재무 데이터   |
| 경영기획의 예상 질문과 피드백 | 실적과 투자계획에 시장이 던질 질문       |
| 실제 검토 의견         | 그 뒤에 나온 애널리스트 리포트의 질문과 쟁점 |

나중에는 공개 데이터 자리에 사내 데이터를 연결해요. 그래서 데이터와 검토 기준만 바꾸면 다른 문서 검토에도 쓸 수 있어야 해요.

## 2. 누가 어떻게 쓰나요?

| 사용자    | 하는 일                             |
| ------ | -------------------------------- |
| 분석 담당자 | 기업 자료를 올리고 근거 점검 결과와 예상 질문을 받아요  |
| 설정 관리자 | 추출 항목과 검토 기준을 바꿔 다른 기업이나 자료에 맞춰요 |
| 평가 담당자 | 예상 질문이 실제 리포트의 쟁점과 얼마나 맞는지 확인해요  |

## 3. 최소 구현 기능

> 수집 코드와 조회 MCP는 이미 있어요. 다만 형태가 제각각인 자료를 파싱하고, 예상 질문을 실제 쟁점과 견줘 평가해야 해서 예상 기술 난이도는 상이에요. 대상이 통신 3사로 좁아서 예상 작업량은 중이에요.

| 기능 | 데모에서 보여줄 것 |
| - | - |
| 근거 데이터 수집 | 통신 3사의 IR 자료, 사업보고서, 재무 데이터, 애널리스트 리포트가 발행일과 출처를 달고 쌓여요. |
| 자료 파싱과 근거 점검 | 올린 자료에서 회사의 주장과 숫자를 뽑아 근거가 모자란 곳을 표시해요. CapEx 같은 숫자는 코드로 계산해 공시와 대조해요. 주제와 맞지 않는 자료가 들어오면 알려줘요. |
| 애널리스트 질문 예측  | 애널리스트가 던질 질문과 추가로 확인할 근거를 자료 속 위치와 함께 정리해요.                                                     |
| 범용 설정 | 입력 자료 종류, 추출 항목, 검토 기준, 출력 양식, 프롬프트, AI 모델을 코드 수정 없이 바꿔요.                                       |
| 예측 평가 | 기준 시점 이전 자료로만 예측하고, 그 뒤에 나온 리포트의 쟁점과 견줘 맞힌 비율을 재요. |


## 4. 최종 산출물 이미지

| 항목        | 내용                                          |
| --------- | ------------------------------------------- |
| 자료 분석 화면  | 회사의 주장과 근거가 나란히 보이고, 숫자를 누르면 계산 과정과 출처로 가요. |
| 예상 질문 리포트 | 애널리스트가 던질 질문과 추가로 확인할 근거가 정리돼요.             |
| 설정 화면     | 추출 항목, 검토 기준, 프롬프트 등을 고쳐요.                  |
| 평가 결과     | 맞힌 것, 놓친 것, 빗나간 것을 점수로 보여줘요.                |

데모 흐름은 이렇게 잡으면 좋아요.

1. 통신사 한 곳의 분기 실적 자료로 예상 질문을 받아요.
2. 이후에 나온 리포트와 견줘요.
3. 기준을 바꿔 예상 질문 및 리포트 결과가 달라지는 걸 보여 줘요.

## 7. FAQ

**Q. 멘토링은 어떻게 진행되나요?**
A. 교수님이 전담 멘토로 언제든 멘토링하고, 주관 팀 현업 담당자도 월 1회 멘토링에 참여해요.

**Q. 예상 질문이 맞았는지는 어떻게 판단하나요?**
A. 정해진 기준은 없어요. 표현이 달라도 같은 쟁점이면 맞힌 것으로 보는 식으로 팀이 기준을 정해요. 기준은 첫 멘토링에서 확인해요.

**Q. 범용화는 어디까지 해야 하나요?**
A. 통신 3사 자료로 동작하면 돼요. 여기에 설정만 바꿔 다른 기업이나 자료로 돌려 보는 시연을 더하면 좋아요.
